## 2023-10-26 - Haversine Distance Closure Optimization
**Learning:** The `haversineKm` distance calculation function in `RightNowView.tsx` creates an internal `toRad` closure on every call. Because it's used extensively in O(N*M) clustering loops to determine distance between map objects, the allocation overhead becomes significant.
**Action:** Always extract constants like `Math.PI / 180` and inline simple math conversions outside of inner functions in heavily iterated loops (e.g., map rendering or clustering logic) to prevent memory allocation overhead per iteration. This yielded a ~4.7x speedup for this function.
## $(date +%Y-%m-%d) - Object.entries().map() React State Anti-Pattern
**Learning:** Found a severe React re-render anti-pattern in `App.tsx` where updating/deleting a single message rebuilt the message array for *every* chat room (`Object.fromEntries(Object.entries(prev).map(...))`). This broke reference equality for all unrelated rooms, causing massive unnecessary rendering cascades.
**Action:** When updating a deep dictionary state (like `Record<string, Message[]>`), avoid mapping over the entire dictionary if the update is localized. Instead, locate the specific key (e.g., `roomId`) that needs updating, and only reconstruct that specific value while spreading the rest of the dictionary (`{ ...prev, [targetRoomId]: updatedArray }`) to preserve references.
## 2025-02-27 - Object.fromEntries(Object.entries().filter()) React State Anti-Pattern
**Learning:** Found a severe React re-render and GC pressure anti-pattern in `App.tsx` and `DiscoverView.tsx` where deleting items or building arrays inside hooks mapped over entire dictionaries/arrays (`Object.fromEntries(Object.entries(prev).filter(...))` and `arr.filter(...).map(...)`). This creates unnecessary intermediate arrays and O(N) overhead.
**Action:** When filtering deep dictionary states, avoid mapping over the entire dictionary if the update is localized. Instead, use a shallow copy and targeted `delete` operations (`{ ...prev }; delete next[targetRoomId]`). For array transforms inside tight loops or `useMemo`, prefer standard `for` loops over `.filter().map()` chains to avoid intermediate array allocations.
## 2025-02-27 - Unnecessary Component Re-renders in DiscoverView
**Learning:** The `DiscoverView` component, a heavy list rendering view, was not wrapped in `React.memo`. Given that it takes complex prop structures (profiles, pulses, multiple callbacks) from a high-level parent (`App.tsx`) that updates frequently on localized state changes (like chat messages or discovery signals), this caused significant unnecessary re-renders of the entire discovery list.
**Action:** Always wrap heavy list components or complex views (like `DiscoverView`) in `React.memo()` to prevent them from re-rendering when unrelated state in their parent component changes, especially when their props are stable or appropriately memoized by the parent.
